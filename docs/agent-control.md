## Instruction — working directory

The CLAUDE.md rule loads on every session in this repo. It tells the agent to check it is working inside MATHutrice-fork, never the original MATHutrice clone, before making any change. It should stay quiet on purely explanatory tasks with no write intent: asked to explain how deduire_niveau_eleve works, the agent answered without mentioning the working directory at all, which is the right call there. I tested it across five angles: a normal write task, an explicit attempt to send it into the original repo, a vaguer version of that same attempt, a theoretical question, and a folder name that shared a substring with the forbidden one. It held up in all five, no false trigger, no missed case. One bullet turned out to be redundant ("the original folder exists for reference only, never write to it"). I removed it and reran all five tests. Behavior was identical with or without it, so it was a genuine no-op: the two remaining, more general lines already covered everything that bullet was supposed to catch.

## Enforcement — block direct push to main

A PreToolUse hook (.claude/hooks/block_push_main.py) checks every Bash command before it runs and blocks any git push that would land on main, whether implicit (git push with no branch, from a main checkout) or explicit (git push origin main). An instruction alone would not have been enough here, because the failure mode is non-deterministic: an agent that avoids pushing to main nine times out of ten can still get it wrong the tenth time, and by then the damage is already on the shared branch. The hook makes that outcome impossible instead of counting on the agent to remember. It took three real fixes to get right, each one caught while actually using it, not staged for the exercise. First, a naive substring check ("push" in command) blocked me from committing the hook itself, because my own commit message contained the words "push" and "main". I fixed that by tokenizing the command with shlex to detect a real git push call. Second, even after that fix, the hook kept blocking any push made from a main checkout, regardless of which branch it actually targeted, so pushing an unrelated branch like main-backup got wrongly blocked too. I fixed that by checking the real refspec target instead of the current branch. Third, the comparison was case sensitive, so git push origin MAIN slipped straight through. I fixed that with a case insensitive comparison. Each fix was retested against the case that broke it plus every case that worked before, with no regressions.
